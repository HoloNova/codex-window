# 多账户：已确认方案与实现边界

单账户完整基线为 `417a471`。用户已批准多账户实现及默认开启的设置同步；本轮在本地实现，不提交、不推送、不操作真实凭据，也不切换现有后台。

## 数据和运行流程

```text
独立登录 → 按真实 accountId 去重 → 保存到对应账号目录（暂停）
                                             ↓
一份 Node.js 后台 → 各账号独立查询/判断/必要时发送 → 各自写本地状态
                                             ↓
                    TUI 选择账号 → 只读本地结果，不因切换请求远端
```

- 一个数据根目录对应一个后台进程。各账号有独立串行异步任务，通过到点定时器和文件通知唤醒，不做 250ms 高频轮询；A 的慢查询、续期或失败不阻塞 B；每账号仍遵循原调度和防重复规则。
- 相同真实账号再次登录只更新其凭据，保留该账号的待确认记录；不会覆盖其他账号，也不创建重复调度。
- 关闭 TUI 不停止任何账号。R 启用、I/F2 暂停、C 查询作用于当前账号；X 暂停所有账号并停止整个后台。
- 新账号默认暂停。添加账号时不暂停当前账号；L 重新登录会先暂停当前账号。即使登录到另一个身份，也按真实身份分开保存，不覆盖原身份。
- 已开始的授权兑换/续期安全完成保存；Esc 返回或切换后，迟到结果不会抢回页面，也不会写到后来选中的账号。
- 全局停止后，已开始的刷新凭据可以完成保存，但在下一次查询/发送前再次检查停止条件。

## 本地布局

```text
~/.codex-window-node/
  accounts.json             # 索引、全局同步开关、全局停止及控制版本号
  auth.json                 # 现有账号 default，原位置保留
  config.json               # 模型/时区/时段/间隔/自动发送开关
  state.json                # 运行控制/额度/待确认/事件（v2）
  pool.lock                 # 整个后台进程互斥
  worker.lock               # default 账号循环互斥
  accounts/
    <SHA-256(accountId)>/
      auth.json
      config.json
      state.json
      worker.lock
      account.lock
```

- 新的 `accounts.json` 使用独立的应用标识和版本，损坏时拒绝操作，不重建或重置账号。
- 原有凭据位置和格式不变，不要求重新登录；state.json 的配置拆到同目录 config.json，其余记录升级为 v2。检测到旧后台仍运行时不迁移，详见 [CONFIG_AND_SCHEDULING.md](CONFIG_AND_SCHEDULING.md)。
- 账号目录 ID 不使用邮箱、Token 或用户输入路径；拒绝目录符号链接和越界路径。索引和凭据私有保存，凭据不进入索引或日志。
- 后台检查目录对应的真实身份，拒绝复制凭据造成的同根目录重复调度。不同根目录及其他工具不在此去重范围内，仍需避免同时开窗同一个账号。
- 不新增 Web、数据库、账号代理、自动换号或账号删除功能。

## 设置同步

- 每账号 config.json 独立保存模型、时区、发送时段、查询间隔及自动发送开关。手工编辑只影响该账号，不自动触发多账户同步。
- 设置页有一个**全局**“同步账号设置”开关，默认开启，作为草稿的一部分保存；Esc 放弃草稿不改变开关。
- 开启时，保存当前设置会写入所有账号；关闭后只保存当前账号。M 选模型和无头 `config` 走同一规则。
- 同步只在保存时发生，不由后台持续覆盖。开启状态下添加新账号，继承发起添加的账号设置；关闭状态下，新账号使用默认设置，时区取运行设备；已有账号不静默改成设备时区。
- 凭据、启停意图、额度缓存、发送待确认、事件和查询计数不复制。**配置实际改变的账号暂停**，需逐个手动启用；配置未变化的其他账号保持原启停状态。
- 打开 L/M 仍先暂停当前账号；S 现在只读打开草稿，语言切换不暂停、不参与账号同步。保存实际变动的业务配置时才暂停受影响账号，同步开启时可能涉及多个账号。
- 修改模型前不请求所有账号的模型目录；同步不保证所有账号都支持该模型。不支持时显示各账号自己的错误，不自动替换模型。需要区别配置时关闭同步。

### 写入与并发

- 账号索引锁串行化添加、设置同步和全局停止；登录等待单账号凭据锁时不持有全局索引锁，避免一个慢请求挡住其他设置和全局停止。同步保存前获取全部目标状态锁并验证数据；等锁期间取消，不写入任何账号。
- 每个文件原子替换；写入开始后同步完成当前批次，不在中途响应取消。若文件系统错误造成部分写入，明确报错，已变动账号保持暂停，可检查后重试；不声称跨文件事务原子性。
- 模型选择没有显式修改同步开关时，以真正获得锁后的最新开关为准，不把更晚的“关闭同步”覆盖回去。
- 暂停、设置变化及全局停止使旧发送许可失效；更晚的停止不能被排队的旧启动覆盖。

## 从正在运行的旧后台切换

本轮没有执行切换。新的入口检测到旧后台时，只展示缓存并提示，不自动停止或替换它。

人工准备切换时：

1. 双 Ctrl+C 关闭**旧版前台**，避免它后续继续操作旧的控制语义。
2. 在项目目录执行 `node dist/cli.js stop`。这会暂停该数据目录的所有账号并请求旧后台优雅退出，不撤回已开始的请求。
3. 执行 `npm start`；新版会等待旧后台退出，拆分配置文件，再启动一份多账户后台。原凭据保留，设置等价迁移，待确认不丢失，不会自动启用任何刚被暂停的账号。
4. A 打开账号弹窗，选择“添加账号”。先检查显示、身份、设置同步效果，再分别 R 启用需要的账号。

其他 Pi/Rust 服务不在上述切换范围内；不得未经授权操作它们。

## 验收

- 非 UI：临时目录/合成凭据/本地 HTTP，验证去重、隔离、同步开关、取消、独立并发循环、全局停止和旧后台检测。
- 人工 UI：A 切换及添加、登录完成后账号归属、各账号额度与日志不串、S 同步开关与 M 一致、Esc/双 Ctrl+C、X 的全局作用。
- 真实多账户运行、真实续期和开窗仍需人工验收；不运行 UI 自动化。
- 日志仍为各账号面板会话累计，不是完整持久历史；搜索和跨会话历史未加入。
