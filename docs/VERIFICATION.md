## 0.1.2：新开窗时序与日志精简

- 当前实施：reset +30 秒检查，resetAt − 当前时间在 18000 ±10 秒内判空闲；每次指令结束后 +30 秒确认，仅明确仍空闲时最多补发一次，再 +30 秒最终确认。普通自动查询与重置检查共用判断，不增加“用户刚工作”的使用率拦截；原额度、模型、时段、暂停及发前快照保护保留。
- 常规查询从每次额度查询完成（包括失败）加间隔计时，不从 POST 结束计时；重置／确认任务独立。手动 C 不发送、不新建任务，也不因查询跨过截止时间而取消已有任务；有效新活动窗口可以取消过时计划。本轮规则取代下面 v0.1.1 历史中的“C 丢弃到期计划”。
- hold.task 可选保存最多两次的预占次数、确认截止时间和许可快照。发送前先落盘占用次数；重启不重置次数，旧 hold 不补发。暂停、配置变化和晚到发送回调不得复活失效任务。确认失败／无效数据消费本次确认截止时间、保留待确认并回到常规查询，不忙循环。
- 回归先失败再修复：原实现立即确认、不保存补发次数；独立审查另发现 C 在 reset 与 reset+30 之间读到空闲会取消计划。新增回归确认后者及“手动查询跨截止时间”均在修复前失败，修复保留独立任务，并仍断言无 POST。自查补齐普通查询提前发送、普通查询跨截止时间，以及失败的手动／普通查询误消费重置任务的边界，均先复现失败再修正。Advisor 指出的失败回调可能清除新控制状态下的替代计时器，也经先失败后修复的回归覆盖；重复观察同一 reset 不推迟计划，新 reset 才变更，新活动窗口可撤销旧计划。
