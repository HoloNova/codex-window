# 最小实现计划

本次按已确认方案实现一个独立的 TypeScript + Node.js 小工具，不移植上游框架。

状态：用户已确认最新 TUI 可用，并授权将当前实现作为单账户完整基线提交。类型检查、构建和 50 项非 UI 测试通过；真实续期、开窗及其他平台仍待进一步验证。下一阶段只讨论多账户设计，未经确认不实施。详见 [VERIFICATION.md](VERIFICATION.md)。

## 主线

独立登录 → 保存/续期凭证 → 查询额度 → 按规则等待 → 必要时发送一次 hello → TUI 展示。

- 一个账号、一个明确选择的订阅模型；不自动换号，不发现或预热其他额度池。
- 默认 Asia/Shanghai、04:30–19:30、每 30 分钟查询；支持必要的时区、时段和间隔设置。
- 超过一个查询间隔才重置：等待；临近重置：安排重置后 90 秒复查。
- 复查发现已有新窗口：不发送。窗口空闲、额度允许且已启用时才发送。
- 数据缺失、查询失败或限制未知时不猜测；不保留固定时间兜底和五分钟重发链。
- 发送前持久化待确认标记，超时/结果不明确不自动重发。观察到活动窗口或用户明确启用并复核后解除。
- 初始暂停；登录、设置修改都暂停。关闭面板不停止后台；暂停只禁止发送，仍可查询。

## 实现顺序

1. 直接 HTTP：设备码及浏览器登录、凭证续期、额度查询、单次请求。
2. 单后台循环：时间规则、持久化启停、防重复发送。
3. 最小 TUI：登录、模型选择、设置、额度、状态、下次动作、启停。
4. 类型检查和本地模拟接口/进程测试；真实账号和终端由用户手动验收。

## 已确认的 TUI 规则

- 所有页面在同一个 TUI 内，统一输入所有权，不混用临时终端问答。
- Esc 返回上一步；主页不退出。Ctrl+C 第一次提示，3 秒内第二次退出前台；后台不随面板退出。
- 设置使用草稿；编辑项 Esc 放弃本项，设置页 Esc 放弃未保存草稿，保存后保持暂停。
- 只更新变化的行；首次/尺寸变化才完整重绘，使用同步输出避免中间帧闪烁。
- 普通按键立即解析，单独 Esc 的序列判断窗口为本地 10ms / SSH 100ms；保留 UTF-8 和完整按键序列重组。
- 状态变化由文件通知触发，5 秒兜底检查；模型目录按账号在前台内存缓存 5 分钟，不因命中缓存而续期或等待账号锁。
- 额度显示剩余百分比，绿→黄→红；低于阈值同时用文字标明。时间、等待、警告、失败、暂停使用统一语义色，支持 NO_COLOR。

## 本轮已确认的结构化 TUI

- 顶部居中显示 `Codex Window Autorefresh`，各模块使用圆角矩形；宽屏订阅卡片与快捷操作并排，窄屏上下排列，短终端使用紧凑信息行。
- 订阅卡片顶部为当前账号与订阅信息，显示所选模型、五小时/周剩余额度及重置时间、启停状态。直接移除“开窗复查”，也不使用“下一步”等名称重新展示该机制；后台规则不变。
- 下方为事件卡片，提示“按 D 查看详细日志”。日志独立页面支持滚轮、方向键、翻页键、Home/End 和滚动条；翻阅历史时不自动跳回底部。
- 本轮只使用现有八条事件快照，在前台会话内继续累计，最多 1000 条；不修改后台状态格式或加入持久日志存储。日志搜索和跨会话完整历史后续再定。
- 登录、模型、设置、字段编辑和等待均为居中圆角弹窗；Esc 逐层返回，双 Ctrl+C 全局退出不变。
- 提示为右下角无边框纯文字，默认 3 秒；首页在事件卡片右下角，可覆盖日志但不得叠字。成功绿、警告黄、错误红、普通反馈青色；第一次 Ctrl+C 的退出确认同样为红色提示。
- 目前仍为单账号，不显示无法工作的“切换账号”入口，不以重新登录覆盖凭证冒充多账户。多账户设计在 UI 人工验收后单独讨论。
- 不运行 UI 自动化，不操作用户登录、设置、启停状态或现有进程；业务和非 UI 回归使用临时目录、模拟 HTTP 验证。

## 边界

- 不依赖或读取 Pi、Codex CLI、旧 Rust 程序的凭证。不安装/修改线上服务。
- 默认独立数据目录 `~/.codex-window-node`；`--home` / `CODEX_WINDOW_HOME` 可指定。
- 状态使用本地 JSON；凭证单独私有保存，不进入日志。后台进程与面板通过文件交互，不增加常驻 HTTP 服务。
- 仅使用 Node.js 标准库；TypeScript 和 Node 类型包为开发依赖。
- 不增加 Web、数据库、插件框架、自动更新、自动开机启动、通知平台或旧格式兼容层。
- Git 提交需要明确授权；本次已授权提交当前单账户基线。推送、发布、部署、真实登录或发送仍需另行授权。
- 旧参考目录在新版开发完成并经用户验收后再清理。
