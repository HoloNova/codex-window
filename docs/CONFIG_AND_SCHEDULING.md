# 配置文件与事件驱动调度

用户已确认本方案。仅实施和本地验证；不迁移真实数据，不停止/重启现有进程，不触发真实请求，不提交或推送。

## 文件职责

- 每账号 `config.json` 保存模型、时区、发送时段、查询间隔和 `enabled`。这是用户配置的唯一来源，可以手动编辑。
- `state.json` 保存查询结果、事件、发送待确认及控制计数，不再重复保存配置。程序内部可组合两个文件提供只读视图，但运行结果写入不能覆盖配置。
- `auth.json` 和根目录 `accounts.json` 职责不变，凭据不进入配置或日志。
- TUI 保存仍遵循全局设置同步开关，并暂停配置实际变动的账号。直接编辑某个账号的配置只影响该账号，不自动同步；手动开启不清除发送待确认，解除待确认仍需 R 复核。
- 非法 JSON、未知时区或其他无效值明确报错，禁止该账号发送，不以默认/旧配置继续发。修正后可恢复处理，不重建损坏文件。
- 停止遇到坏配置时仍持久化运行停止标记，不覆盖坏文件。之后修复为 enabled=true 不能在重启时自动绕过该停止；先设为 false 安全启动，或显式 R 复核。

## 时区

从 Node 内置 IANA 时区目录搜索选择，包含 UTC 和运行环境识别的默认时区。新默认配置采用运行设备时区（SSH 是服务器/运行环境，不是客户端电脑）。已有账号保留等价设置；旧时区别名迁移时规范化，不更改时间含义。同步开启时，新账号仍继承发起账号设置。

校验采用目录查找，不在每次状态读取时创建格式化器；调度计算的日期格式化器按时区复用。

## 后台

- 每账号一条串行异步任务，等待下一次实际查询/复查时间；不再每 250ms 检查是否到点。
- 目录级文件通知处理配置修改、手动查询、暂停/启用和停止；新增账号由根索引通知启动。通知合并，避免自己写结果形成忙循环。
- 网络等待期间也处理停止通知，取消可取消的读请求；已开始的凭据续期安全落盘，已发送请求仍安全收尾。
- 保留低频兜底，处理通知丢失和修复后的文件；最终发送前直接重读并验证当前配置、运行状态、全局停止及账号身份。
- 对比配置快照，手工改模型/时段/开关也会使旧查询的发送许可失效，不依赖用户手动增加控制计数。
- 模型、时区、时段、查询间隔或 enabled 实际变化后重新安排工作；只改文件权限、时间戳等元数据不追加查询或丢弃开窗计划。发送许可仍核对完整文件快照（含身份和时间戳），不能用业务值相同绕过查询期间的改动或 A→B→A 变化。错误配置修复后，即使业务值与出错前相同也重新查询。
- 程序启动、后台定时和用户手动查询保留；正常后台运行期间，重新打开面板只加载缓存及上次成功查询时间。恰逢到期的后台查询不算面板新增请求。常规查询的下一时间为每次额度查询完成（包括失败）加设定间隔，默认 30 分钟；不能用发送结束时间代替查询完成时间，也不再按本地整点对齐。账号之间不互相等待网络，账号锁及全局停止保护保留。
- 常规查询、重置后检查、开窗确认共用每账号已有串行任务及 Wakeup，但各自有独立截止时间，不增加后台循环。任何查询顺延常规计时，不取消另外两个任务；同时到期的自动任务共用一次新查询。
- C 不发送、不创建任务，也不消费已有重置／确认任务；即使手动查询跨过截止时间，自动任务仍独立存在。有效观察确认用户已开启新窗口，才撤销旧重置计划；控制状态变化也可取消许可。已到期的自动任务随后仍先发起独立新查询，不以手动结果直接发送。
- 下次动作区分定时查询、条件性计划开窗和开窗结果确认；读取后台保存的 nextRefresh／hold.task.confirmAt，不从缓存推测必然发送。暂停、无模型或旧／终止待确认不展示可执行开窗；后台未发布计划时显示“正在安排下次查询”。
- 查询只保留一条结果记录，包含必要原因；计划只记新增、变更或取消，不拆“请求／开始／完成”多条，不写“计划不变”。发送、30 秒后确认、补发、确认成功及失败原因保留。导航和草稿提示不进入日志，启用／暂停／保存只记一次。继续保存最近八条，面板会话最多 1000 条，不增加日志文件。D 详情按信息（灰）、执行（青）、成功（绿）、注意（黄）、错误（红）分类，保留文字标签；首页三行预览保持原样。

## 已确认的开窗规则

1. 自动查询发现 reset 在下一个查询间隔内，安排 reset + 30 秒的新查询；超过间隔则等常规查询。普通自动查询和重置后检查采用同一开窗判断。
2. 观察数据新鲜、五小时／周结构和服务端限制有效时，resetAt − 当前时间在 18000 ±10 秒（含边界）内就按未开窗处理，不额外用使用率拦截刚开始工作的用户。接受偶发重叠；暂停、模型、允许时段及周额度／账号限制仍保留。过期 reset、超出支持范围或时间不一致不能判为开窗成功。
3. 每次 POST 前持久化次数及待确认，发送前再核对完整配置快照、generation、账号及应用许可；一次任务总共最多两次 POST。先预占次数、清空确认截止时间，再发送；落盘失败不发送，进程中途退出不重复使用该次数。
4. 指令结束时保存完成时间 + 30 秒作为确认截止时间，不立即查。只有在该截止时间之后开始的新查询仍明确空闲，才允许第二次发送；补发结束后再等 30 秒作最终确认。等待期间启动的早期查询，即使完成时已过截止时间，也不能授权补发。
5. 有效观察到剩余时间为正且小于 17990 秒的活动倒计时，解除对应待确认并记录成功；请求完成不等于开窗成功。最终仍空闲、数据异常或确认查询失败时，停止补发，保留待确认，常规查询继续，不重置次数、不形成即时重试循环。
6. hold.task 向后兼容地保存 attempts（1 或 2）、confirmAt（时间或 null）、generation 和 configKey。这里 task.configKey 标识业务配置，不含文件权限／时间戳，避免 Windows 重设 ACL 或重开程序误撤销任务；每次实际发送仍用本轮查询的完整 State.configKey 核验。重启保留次数与有效确认截止时间；旧 hold 没有 task 时只读、不补发，旧完整文件 key 的 task 可读取但不获得新补发机会。暂停、控制计数改变或观察到不同业务配置撤销旧任务补发许可，晚到回调不得恢复它。任务间未被观察到的手工 A→B→A 修改不承诺检测；查询到 POST 之间的 A→B→A 仍由完整快照拦截。显式 R 仍按原规则复核并清除待确认，允许新任务。
7. Windows 竞争锁文件时，只有对该锁文件的 open 遇到 EPERM／EACCES／EBUSY 才在原超时和取消边界内等待重试。无法读取的 owner 不是死亡 owner，不删除、不抢占；永久拒绝到期失败并保留原异常原因，格式错误和其他读写错误仍立即报错。

## 迁移与切换

- 旧版 state.json 的配置拆到新文件，其余结果和待确认记录保留；不要求重新登录。
- 检测到旧格式仍有后台持锁时不迁移或替换。新版可以提示/读取缓存，需用户单独安排停止旧后台后再切换。
- 请求停止旧后台时仍写旧格式控制，不能先把文件升级到旧进程不认识的格式。
- 每个文件原子写入；关闭发送先发布配置禁用，开启发送先保存复核结果、再次核对配置快照，再发布启用。运行结果写入不回写配置，显式保存检测已观察到的配置冲突。编辑器不遵守应用文件锁，不能承诺任意并发写入的原子事务，避免同时在编辑器与 TUI/CLI 保存。
- 已兑换 OAuth 先保存为禁止使用的凭据，配置暂停成功落盘后才解除该禁止；配置写入失败不会丢新 Token 或让登录账号自动发送。

## 验证边界

只用临时目录、合成凭据和本地 HTTP。覆盖旧格式迁移/拒绝在线迁移、手工配置修改、错误与修复、发前最新配置检查、通知与定时唤醒、停止续期边界、多账户隔离及设置同步。用合成状态反复读取比较内存，不能把实验结果当作真实后台已优化。

时区选择和自适应界面由用户手动验收，禁止 UI 自动化。真实切换及运行资源收益另行授权和验收。
