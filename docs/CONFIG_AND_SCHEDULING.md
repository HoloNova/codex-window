# 配置文件与事件驱动调度

用户已确认本方案。仅实施和本地验证；不迁移真实数据，不停止/重启现有进程，不触发真实请求，不提交或推送。

## 文件职责

- 每账号 `config.json` 保存模型、时区、发送时段、查询间隔和 `enabled`。这是用户配置的唯一来源，可以手动编辑。
- `state.json` 保存查询结果、事件、发送待确认及控制计数，不再重复保存配置。程序内部可组合两个文件提供只读视图，但运行结果写入不能覆盖配置。
- `auth.json` 和根目录 `accounts.json` 职责不变，凭据不进入配置或日志。
- TUI 保存仍遵循全局设置同步开关，并暂停配置实际变动的账号。直接编辑某个账号的配置只影响该账号，不自动同步；手动开启不清除发送待确认，解除待确认仍需 R 复核。
- 非法 JSON、未知时区或其他无效值明确报错，禁止该账号发送，不以默认/旧配置继续发。修正后可恢复处理，不重建损坏文件。
- 停止遇到坏配置时仍持久化运行停止标记，不覆盖坏文件。之后修复为 enabled=true 不能在重启时自动绕过该停止；先设为 false 安全启动，或显式 R 复核。

## 时区

从 Node 内置 IANA 时区目录搜索选择，包含 UTC 和运行环境识别的默认时区。新默认配置采用运行设备时区（SSH 是服务器/运行环境，不是客户端电脑）。已有账号保留等价设置；旧时区别名迁移时规范化，不更改时间含义。同步开启时，新账号仍继承发起账号设置。

校验采用目录查找，不在每次状态读取时创建格式化器；调度计算的日期格式化器按时区复用。

## 后台

- 每账号一条串行异步任务，等待下一次实际查询/复查时间；不再每 250ms 检查是否到点。
- 目录级文件通知处理配置修改、手动查询、暂停/启用和停止；新增账号由根索引通知启动。通知合并，避免自己写结果形成忙循环。
- 网络等待期间也处理停止通知，取消可取消的读请求；已开始的凭据续期安全落盘，已发送请求仍安全收尾。
- 保留低频兜底，处理通知丢失和修复后的文件；最终发送前直接重读并验证当前配置、运行状态、全局停止及账号身份。
- 对比配置快照，手工改模型/时段/开关也会使旧查询的发送许可失效，不依赖用户手动增加控制计数。
- 配置修改后重新安排工作，账号之间不互相等待网络。所有旧的额度、防重复发送、锁及全局停止规则保留。

## 迁移与切换

- 旧版 state.json 的配置拆到新文件，其余结果和待确认记录保留；不要求重新登录。
- 检测到旧格式仍有后台持锁时不迁移或替换。新版可以提示/读取缓存，需用户单独安排停止旧后台后再切换。
- 请求停止旧后台时仍写旧格式控制，不能先把文件升级到旧进程不认识的格式。
- 每个文件原子写入；关闭发送先发布配置禁用，开启发送先保存复核结果、再次核对配置快照，再发布启用。运行结果写入不回写配置，显式保存检测已观察到的配置冲突。编辑器不遵守应用文件锁，不能承诺任意并发写入的原子事务，避免同时在编辑器与 TUI/CLI 保存。
- 已兑换 OAuth 先保存为禁止使用的凭据，配置暂停成功落盘后才解除该禁止；配置写入失败不会丢新 Token 或让登录账号自动发送。

## 验证边界

只用临时目录、合成凭据和本地 HTTP。覆盖旧格式迁移/拒绝在线迁移、手工配置修改、错误与修复、发前最新配置检查、通知与定时唤醒、停止续期边界、多账户隔离及设置同步。用合成状态反复读取比较内存，不能把实验结果当作真实后台已优化。

时区选择和自适应界面由用户手动验收，禁止 UI 自动化。真实切换及运行资源收益另行授权和验收。
